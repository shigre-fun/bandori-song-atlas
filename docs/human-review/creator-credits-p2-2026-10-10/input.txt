# バンドリ楽曲録 P2 人間確認回答

【Codexへの指示】

これは最新の creator-credit-human-review 台帳の
P2 taskに対する人間確認結果です。

テンプレート生成時の基準HEAD：

e014091046bab48008084a5fa9f01076c5a9f693

対象はP2のみです。

生成時点のP2内訳：

- CREDIT_COLLECTION: 97 task
- CREATOR_IDENTITY: 131 task
- CREATOR_REGISTRATION: 131 task
- ROLE_REVIEW: 68 task
- ALIAS_REVIEW: 1 task
- SPLIT_REVIEW: 53 task
- 合計: 481 task

CREATOR_IDENTITY / CREATOR_REGISTRATIONは、
同じcandidateKeyについて繰り返される回答を
Creator単位に集約してあります。

# ==================================================
■ 最重要適用ルール

1. "" の中に回答がある項目だけhuman reviewとして扱う。
2. "" が空の項目は未回答。
推測・自動補完しない。
3. 回答値として基本的に以下を使用する。
    
    "はい"
    "いいえ"
    "保留"
    "不明"
    "なし"
    
4. credit原文欄には、
人間が確認した文字列を記号・空白・括弧も含めて
原則そのまま保存する。
5. 「欄なし」と記載された場合のみ、
対象画面・公式資料にそのrole欄自体が存在しないことを
人間確認したものとして扱う。
6. 「不明」と「欄なし」は別物。
7. Creator登録について、
aliasesがない場合は
    
    aliases="[]"
    
    と明示する。
    
8. affiliationがないと確認した場合は
    
    affiliation="なし"
    
    と明示する。
    
    分からない場合は
    
    affiliation="不明"
    
    とする。
    
9. samePersonAsは、
    
    新規Creatorなら
    samePersonAs="既存IDなし"
    
    既存Creatorなら
    samePersonAs="cr-XXXX"
    
    とする。
    
10. identityConfirmed="はい"でも、
各creditの
「上記Creatorと同一」
が空欄または保留なら、
そのrecordへrelationを自動展開しない。
11. identityConfirmed="いいえ（複数主体）"
のように回答されたcandidateは、
1 Creatorとして登録しない。
12. candidate自体が複数主体だった場合、
対応するSPLIT_REVIEWがあればその回答を使用する。
対応するsplit taskがなければ、新しいhuman ToDoとして残す。
13. CREDIT_COLLECTIONで新しいCreator名が判明しても、
名前だけでCreator masterへ自動登録しない。
raw creditを反映した上でidentity/registration ToDoへ送る。
14. SPLIT_REVIEWで境界だけ確定しても、
各部分のidentityが未解決なら、
identity未解決として残す。
15. P0 / P1で既に解決したrelationを壊さない。
16. P3以下のidentityを、
P2 split回答だけを理由に勝手に解決しない。
17. Elements Garden / SUPA LOVE / Dream Monster等の所属表記を、
個人Creatorとorganization Creatorの二重参加として数えない。
18. current repositoryがこのテンプレートの基準HEADから進んでいる場合、
currentのtaskId / candidateKey / game+recordId+roleを照合する。
一致確認できたfieldだけpatchする。
19. Work identityを変更しない。
20. unrelated credit / unrelated fieldを変更しない。
21. 回答適用後はToDo台帳を再生成する。
22. unmappedCurrentUnresolved=0を維持する。
23. 解決済みP2だけを台帳から除外する。
24. 人間回答が不足しているものはP2または適切なpriorityで残す。
25. 明示的な追加指示がない限り
commit / push / deployは行わない。
